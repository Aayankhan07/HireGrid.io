# HireGrid.io System Threat Model (STRIDE)

This document is automatically generated by the threat modeler script. It describes the key assets, boundaries, data flows, and threats analyzed according to the STRIDE methodology.

## 1. System Architecture Boundaries & Assets

### Trust Boundaries
1. **Client (Browser) <--> Backend API (FastAPI)**: Communication occurs over HTTP/HTTPS. Credentials, cookies, and tokens cross this boundary.
2. **Backend API <--> Database (SQLite)**: Core system reads and writes to local SQLite database `hiregrid_io.db`.
3. **Backend API <--> System Filesystem**: CV documents are parsed from uploaded multipart data streams.

### Core Assets
* **User Accounts**: Login credentials, passwords (hashed), roles.
* **Candidate CV Resumes**: Sensitive PDF documents uploaded by recruiters containing personal identifiable information (PII).
* **NLP Models / Semantic Scores**: Intellectual property and system scoring outputs.

## 2. STRIDE Threat Analysis

| Threat Category | Description | Mitigations Implemented | Status |
| :--- | :--- | :--- | :--- |
| **S**poofing | Attacker logs in as another recruiter or bypasses OAuth. | Google OAuth2 validation using Google tokeninfo API endpoints. Secure session HMAC-signed tokens generated on the server. | **Mitigated** |
| **T**ampering | Attacker intercepts/modifies uploads or SQL queries. | SQL parameterization used in all database queries. Communication over HTTPS (in production). | **Mitigated** |
| **R**epudiation | User denies launching resume screening pipelines. | System outputs audit logs. In production, persistent auditing should be written to database. | **Partially Mitigated** |
| **I**nformation Disclosure | Unauthenticated user queries `/api/analyze` to read CV data. | Enforced Bearer Token Authorization check in `/api/analyze` and `/api/analyze/stream` endpoints. | **Mitigated** |
| **D**enial of Service | Large files uploaded repeatedly to exhaust server memory/transformers. | Limit file payload sizes in gateway proxy. Use run_in_threadpool to offload heavy calculations. | **Partially Mitigated** |
| **E**levation of Privilege | Signup payload containing arbitrary `role` parameter changes privileges. | Forced role mapping for new self-registered accounts to `Recruiter` inside backend auth endpoints. | **Mitigated** |

## 3. Recommended Future Remediation
1. **Request Rate Limiting**: Implement rate limiting for API endpoints (e.g., using `slowapi` or redis-based limiters) to prevent Denial of Service via repeat file uploads.
2. **File Validation**: Validate PDF structures and MIME types (not just file extensions) before executing layout extraction to prevent arbitrary file execution attacks.
3. **Database Audit Logs**: Store all analysis triggers in a persistent audit trail.
